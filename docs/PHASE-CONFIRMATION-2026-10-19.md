# 三阶段确认与模型选择

2026-10-19 按用户最新要求调整。先前实现会在转写与装配后自动分析术语，会话也缺少后台强制执行的跨阶段确认。现将术语移到第二阶段，并由面板单独确认三个阶段。阶段内继续允许修复和续跑，保留原输入、已完成结果及预算。

| 阶段 | 一次确认后的执行范围 | 模型选择与结束行为 |
|---|---|---|
| 转写 | 输入分析、范围处理、页面图、结构准备、转写、校验、装配；Markdown 只检查现有原文 | 面板选择编排模型及转写模型，沿用已确认的兜底配置；装配完成后停止 |
| 术语分析与翻译 | 术语分析、翻译准备、翻译、译文校验 | 面板选择编排模型与 LinguaGacha 模型；术语和翻译使用本次确认的模型，完成后停止 |
| 审校与发布 | 联合审校正文与术语、校验补丁、发布阅读成品 | 面板选择审校模型、分包模型及思考档位；按钮明确包含审校通过后发布，存在未解决问题则停止 |

后台将确认阶段、模型和确认时间保存在任务的 phaseApproval。document_pipeline 工具没有确认阶段的动作，旧会话绑定和会话中的续跑指令不能产生下一阶段的许可。后台处理入口、直接审校入口和发布入口均核对确认记录。模型配置与确认记录不一致时停止，要求面板重新确认。该检查由程序完成，不增加模型请求，也不要求模型回写哈希。

新建任务先保存，再打开确认面板；取消不会派发模型。已完成步骤直接复用，修正了原先在跳过检查前将第一步标为运行中的行为，避免重复处理。第二阶段不提前准备第三阶段的审校任务。面板同时修复审校模型目录缺失、刷新时重置未提交选择的问题，并取消确认与派发之间重复的会话模型设置请求。

| 验证 | 结果与范围 |
|---|---|
| 自动化测试 | 139 项通过。覆盖未确认请求拒绝、旧会话不能代替确认、模型必选、审校发布授权、确认记录持久化、模型变化拦截、完成步骤复用及审校失败阻止发布 |
| 浏览器操作 | 使用实际 client.js 和隔离 TaskManager，依次完成三次面板确认；取消无执行事件；阶段之间等待；刷新页面仍要求下一阶段确认；审校目录可选，确认后仅执行审校与发布 |
| 模型与发布替身 | 浏览器测试替换了付费处理与发布内容，只验证界面操作、确认保存及阶段调度；没有调用真实模型或发布真实文献。测试替身曾缺少 publication.files 导致完成页报错，补齐替身字段后完成页正常显示 |
| 宿主范围 | 本轮没有重载正在运行的 DeepSeek Harness，也未验证其进程已加载新模块；需重新加载插件或重启宿主后使用新确认流程 |
