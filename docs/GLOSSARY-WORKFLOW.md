# 术语与正文联合审校流程

2026-10-16。所有新书、论文、章节、合集及已有 Markdown 均采用全文提取、一次清洗与归并、翻译、正文与术语联合审校、更新公共表的顺序。PDF 装配成功后自动进入术语阶段。一次清洗指每个候选只接受一轮语义处理；长文可以分批执行，不要求整本书放入一个请求。

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| 全文提取 | LinguaGacha 读取全部正文、标题与注释，返回候选和原文证据；复用有效旧提取记录 | 全部输入单元有返回，实际模型输入完整 |
| 程序清洗 | 核查格式和原文证据，合并完全重复项 | 不将缺失或伪造证据当作有效候选 |
| 一次清洗与归并 | LinguaGacha 同时处理术语边界、公共旧项、译名冲突、姓名别名、词形和概念归并 | 每个候选明确保留或删除，返回标识与覆盖完整 |
| 翻译 | 使用固定的本书合并表；不能确定的含义保留原词，记录疑点 | 完整产物、段落与来源映射检查通过 |
| 联合审校 | 对照完整原译文、本书表、概念分组、删除记录、公共候选与待核查项 | 报告对应当前文件版本，明确通过或仍需修改 |
| 公共表更新 | 仅将联合审校通过的可复用候选加入公共库 | 不覆盖既有不同译名；并发冲突整组保留在本书 |

不再独立执行逐项清洗、同键冲突裁定、全表归并、全表复核及自动返工这几轮串行模型检查。术语判断的争议交给后续正文审校，文件损坏、单元缺失、原文变更、标识异常与实际输入遭修改仍会停止流程。模型声明有歧义或姓名译法不一致时，整组保留原词进入本书表，禁止进入公共候选，并将建议译法和理由交给联合审校。

## 请求与产物

全文提取使用 prompts/glossary-analysis.txt，清洗归并使用 prompts/glossary-consolidation.txt。沿用官方 CLI translate 与自定义提示词，不自动改变 LinguaGacha 全局模型配置。术语分析与翻译共用当前模型及并发设置；用户调整并发时，两阶段保持一致。原文和候选均作为数据，不能充当操作指令。清洗输入合并同一原词的提议、压缩重复说明，优先引用提取证据所在段落，保留一至两处局部原文。多个条目共用的相同引文只发送一次。相关拼写、全名简称及可识别的词形尽量分在同批；这些关联仅用于分批，不自动断言概念相同。分批索引只作参考，不能据此伪造候选。跨批关系和未展示的原文含义由联合审校核对完整正文。

| 任务内产物 | 内容 |
|---|---|
| glossary/source.md、structural-cleaned.json | 完整原文快照、格式和证据清洗记录 |
| glossary/cleaning-inventory.json | 实际单轮清洗单元、共享引文与参考索引 |
| glossary/semantic-groups.json、semantic-rejections.json | 概念与别名处理，以及最终删除理由 |
| glossary/review-issues.json | 需要联合审校的疑点、建议译法与保留原词的处理方式 |
| glossary/common-snapshot.json、book-overrides.json | 本书采用的公共快照和本书特定用法 |
| glossary/public-candidates.json | 尚未写入公共表、等待联合审校的可复用候选 |
| glossary/effective.json、任务根目录 glossary.json | 本书翻译用表，原词键唯一 |
| glossary/analysis、consolidation | 原始请求、实际输入证明、原始模型返回、导出、缓存与恢复记录 |
| glossary/pipeline-receipt.json | 版本 4，cleaningCompleted=true；semanticVerified=false，不能冒充联合审校结论 |
| review/report.md | 原译文、术语表和疑点文件的版本标记及联合审校结论 |
| glossary/public-promotion.json | 审校后新增、跳过的公共项及审校来源；不改变本书固定快照 |

公共库在 .pipeline/glossaries/common.json；尚不存在时只读 lingua/glossaries/master_academic.json，不因准备翻译就初始化或修改公共库。公共更新保留历史副本、采用原子替换和写入锁。并发期间新增的不同译名不会导致整篇重新分析；相关候选整组跳过公共更新，本书译法保留。重复登记同一有效审校不会重复增加公共项。

## 联合审校报告

报告必须含当前原文、译文、glossary.json 和 review-issues.json 的 SHA-256 标记。程序核验这些标记及实际文件，不以报告存在就认定审校通过。正文和术语都通过、待核查项已经处理，审校者才能给出 pass。仍有待处理意见时使用 needs-work。程序不额外请求一个模型复核报告。

```html
<!-- dsh-review-source:原文SHA256 -->
<!-- dsh-review-target:译文SHA256 -->
<!-- dsh-review-glossary:术语SHA256 -->
<!-- dsh-review-issues:疑点SHA256 -->
<!-- dsh-review-status:pass -->
```

仅 pass 会触发公共候选更新；缺少术语标记或版本不匹配会要求重新联合审校。正式审校仍需核查具体证据，自动化测试不能证明模型译名正确。版本 2、3 的旧产物保留，但不冒充新版已完成；来源、提示词、模型配置均一致且实际输入完整的旧提取结果可以复用。暂停恢复只补未完成单元，不自动重跑转写。内容审核返回 content_filter、模型请求超时或供应商返回长度截断时保留原始请求，最多追加重试 3 次；复用已完成单元，只补未完成结果。这些失败会终止 CLI 自行重复请求，程序统一计数。次数随任务回执保存，重启或再次点击不会重置；用尽后停止。普通术语歧义仍留待联合审校，不增加语义复核轮次。

## 验证边界

当前 71 项自动测试通过，覆盖单轮调用、删除整句、姓名和词形一致性处理、歧义保留原词、公共更新延后、审校版本、并发冲突和恢复等行为。对《造就人》的输入测量保留全部 197 个原词键，新清洗分 4 批共 143,749 字符；旧流程单独的全表归并请求为 262,494 字符，减少约 45%。旧流程另有逐项清洗、冲突裁定和独立复核，未计入该比较。测量仅重新构造候选及引文，没有启动新的模型请求，详见 glossary-payload-measurement.json。实际耗时、模型清洗质量和原生宿主交互仍需另行验证。

提高输出预算时，可以复用同一原文、提示词和模型下已经完整且有输入证明的结果；原始回执仍保留旧预算，不冒充新调用。部分任务从输入证明还原完整单元清单，再仅发送未完成项。降低预算或改变模型、原文、提示词等条件不按提高预算的规则复用。2026-10-16 的本次续跑将 MiMo-v2.6-pro 输出上限提高到 65,536 tokens，模型请求超时放宽到 1,800 秒，并发保持 4。
