## 目标布局与实施顺序

建议将长期数据放在 `/Users/hao/Library/Application Support/DSH/PaperReader`，插件源码与可升级的处理运行时分别管理。此路径为方案建议，当前配置未切换。代码升级不应要求移动全部书籍，插件删除也不应连带删除文献。

| 目录 | 内容 |
|---|---|
| `documents/<documentId>/` | 原始 PDF、原文、译文、阅读版本、实际引用的图片和附件 |
| `tasks/<taskId>/` | 阶段状态、交付回执、转写预算、日志、审计、翻译工程 |
| `catalog/` | SQLite、文件夹、隐藏状态、书签和文档版本 |
| `imports/<importId>/` | 来源映射、逐文件大小和 SHA-256、迁移结果、回滚信息 |
| `runtime/<version>/` | 经依赖检查的处理脚本与阶段规则；凭证不进入运行时包 |

先实现路径解析层，分开 `dataRoot`、`runtimeRoot`、`legacyRoot` 和发布目标。继续保留当前默认配置，直到副本通过验收。已有文献可先迁入，随后迁移处理运行时，避免把全部脚本和 15 GB 数据一次性改动。

复制阶段应从暂停写入或一致快照开始，在目标临时目录生成逐文件清单并计算 SHA-256，复制完成后逐项核对。迁移对象应来自实际引用关系，同时保留审计和预算记录；不能只复制文献库当前可见的 20 篇，也不能按文件夹名称直接认定全部内容已完成。未完成书籍的逐页 JSON、脚注、交付状态和耗用次数也必须保留。

路径改写只处理已知路径字段和经解析的附件链接，不对所有文本全局替换。任务 ID、documentId、块 ID及原始来源标识保持稳定。`legacy.key` 当前包含旧目录并参与识别历史任务，应保留为来源标识，另加存储位置字段；否则重新导入可能生成重复任务。SQLite 中的载荷和成果路径也需同步迁移，不能只改 task.json 后清空数据库，否则文件夹与隐藏状态可能丢失。

配置、密钥和外部工具需单独清点。凭证继续由现有凭证服务或明确的本机配置提供，迁移报告仅记录是否可用。不能将旧项目配置、浏览器登录资料或含密钥的环境文件打包进插件。运行时尚需审查 Python 的传递导入、固定路径和外部命令；本轮静态扫描仅识别了依赖旧项目的 7 个插件模块，没有完成 Python 运行时封装。

## 验收和回滚

| 验收范围 | 必须满足的条件 |
|---|---|
| 文件完整性 | 迁移清单内全部文件大小及 SHA-256 一致，附件链接均能解析，未完成项有明确记录 |
| 文献与整理 | 可读文献、全部历史任务、文件夹、隐藏状态与迁移前一致，无重复导入 |
| 阅读 | 原文、译文、PDF、章节目录、脚注、逐段对照及书签能正常打开 |
| 接续 | 在副本中接续现有任务，转写耗用次数与交付回执延续，无重复计费调用 |
| 独立性 | 将旧根设为不可访问后，运行时检查、读取、检索和适当的处理样例仍成功 |
| 切换 | 验收后一次性切换工作区；旧目录和原配置保留，发生问题时恢复原配置 |

复制、路径核对、接续验证和正式切换应分别记录状态。复制成功不能替代内容审校，也不能证明处理流程已经独立。正式迁移前无需删除旧项目；旧项目清理应作为另外一项有明确范围的工作。
